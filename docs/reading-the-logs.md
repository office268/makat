# איפה קוראים את היומן

לשליפה חיה יש יומן חקירה: כל כתובת שנפתחה, לאן הופנינו בפועל, גודל
הדף, כותרתו, מה נשלח למודל ומה הוא ענה. היומן נכתב לשלושה מקומות,
ולכל אחד מהם קהל אחר.

## 1. המסך

`lookup_jobs.log` ו-`lookup_jobs.diagnosis` נשמרים בבסיס הנתונים, ו-
`to_dict()` מעלה מהם למסך את *פרטי החיפוש* (200 השורות האחרונות) ואת
*איפה זה נעצר*. זה מה שרואה מי שיושב מול האפליקציה.

תקרות: `LOOKUP_LOG_CHARS` (24,000), `LOOKUP_LOG_LINES` (200),
והאבחון חתוך ל-8,000 תווים.

## 2. יומן הריצה של Railway

אותן שורות בדיוק נכתבות ל-stdout, ו-Railway אוסף אותן מיומן המכולה.
זה המקום שאפשר לקרוא ממנו **מרחוק, בלי גישה לבסיס הנתונים ובלי שמישהו
יעתיק את המסך ביד** - וזו הסיבה שהוא קיים.

כל שורה נושאת את הסימן `[makat]`, כי רוב היומן הוא שורות גישה של
gunicorn. הבלוק נכתב בכתיבה אחת כדי שלא יתערבב עם עובד מקביל, והשורה
שלפני האחרונה היא הסיבה בשורה אחת: `✗ נעצר ב: <שלב> - <פירוט>`.

```
[makat] ── שליפה 137 · קטלוג יצרן לפי שלדה · פיג'ו צרפת 5008 2020 · VF3M45… · רפידות בלמים
[makat] → ScraperAPI: https://partsouq.com/en/search/all?q=VF3M45… (render=כן · תקציב 55ש)
[makat]   ← HTTP 403 Forbidden
[makat] ✗ נעצר ב: הבאת הדף - האתר החזיר 403
[makat] ── סוף (4 שורות)
```

מפתחות (`api_key`, `token`, `secret`, `password`) נחתכים ל-`***` לפני
הכתיבה. היומן ממילא רושם את כתובת היעד ולא את הכתובת הבנויה, אבל
היומן הזה קריא מהדשבורד ולכן החיתוך הוא חגורה שנייה.

כיבוי: `CATALOG_TRACE_STDOUT=0`. כיבוי היומן כולו: `CATALOG_TRACE=0`.

### לקרוא אותו מכאן

בסביבת פיתוח שיש בה את Railway MCP:

```
mcp__Railway__get-logs
  projectId:     dafd0ef0-464d-4bc3-b3f0-4db7895ea5ff   (makat)
  serviceId:     2b8c77d2-72ed-48da-b2c9-cb6c144a25bf   (web)
  environmentId: 712dc75a-3ea3-4094-8830-d7132258cd26   (production)
  filter:        makat
```

בלי `filter` היומן מוצף בשורות גישה. עם `types: ["build"]` מקבלים את
יומן הבנייה במקום את יומן הריצה.

## 3. מה *לא* נעשה, ולמה

**לא כותבים לקובץ בתוך המכולה.** מכולת Railway היא ארעית ואין לה דיסק
קבוע; קובץ שנכתב אליה נמחק בפריסה הבאה, ואי אפשר לקרוא אותו מבחוץ.
זה בדיוק מה ש-stdout כבר פותר.

**לא מחזירים יומנים לגיט.** כדי שקובץ יומן יגיע ל-repo, השרת צריך
הרשאת כתיבה ל-git - סוד נוסף בפרודקשן, היסטוריה שמתמלאת רעש, וכתובות
ומזהי רכב שנכנסים לענף לצמיתות. יומן ריצה אינו קוד מקור.

## מה שעדיין פתוח

לשורות `lookup_jobs` אין ניקוי. יש `prune_cache` ל-`LookupCache` ו-
`prune_activity` ליומן הפעילות, אבל עבודות שליפה ישנות נשארות
לצמיתות, כל אחת עם עד ~32KB טקסט.
