# קטלוג מק"טים לחלקי רכב

אפליקציית web בפייתון לניהול וזיהוי מק"טים של חלקי חילוף לרכב.

**הרעיון המרכזי:** תמונה של חלק לא יכולה להחזיר מק"ט מדויק — שתי רפידות בלם עם
מק"טים שונים נראות זהות בצילום. לכן המערכת מפרידה בין שני מקורות מידע ומצליבה ביניהם:

```
מספר רישוי  →  רכב מדויק (יצרן, דגם, שנה, קוד מנוע)   ← מצמצם את מרחב החיפוש
                                  ↓
תמונה / תיאור  →  סוג החלק ("דיסק בלם קדמי")           ← זה מה ש-AI עושה טוב
                                  ↓
                    הצטלבות  →  מק"ט יחיד + מחיר
```

## הרצה מהירה

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export FLASK_APP=app:create_app
flask db upgrade            # יוצר את הסכימה
python scripts/seed.py      # טוען קטלוג דמו: 113 מק"טים ל-10 דגמי רכב
python run.py               # http://127.0.0.1:5000/demo
```

בכניסה הראשונה נרשמים ב-`/signup` — הנרשם הופך לבעלים של הארגון.

במסך הדמו אפשר ללחוץ על אחד ממספרי הרישוי לדוגמה, לכתוב "רפידות קדמיות"
או "פילטר שמן", ולקבל את המק"ט המתאים בדיוק לרכב הזה.

## מה יש במערכת

| מסך | מה הוא עושה |
|---|---|
| `/demo` | זיהוי מק"ט: מספר רישוי + חלק ← מק"ט ומחיר |
| `/parts` | קטלוג מלא עם חיפוש חופשי, סינון ועימוד |
| `/parts/<id>` | כרטיס מק"ט: מחירים, מלאי, מק"טים מקבילים, התאמות, ספקים |
| `/vehicles` | חיפוש חלפים לפי יצרן/דגם/שנה |
| `/import` | ייבוא מחירוני ספקים מקובץ CSV |
| `/export.csv` | ייצוא תוצאות החיפוש הנוכחיות |

## ארגונים, משתמשים והרשאות

המערכת בנויה לריבוי לקוחות, בשתי שכבות:

| שכבה | טבלאות | מי רואה |
|---|---|---|
| **קטלוג משותף** | `parts`, `manufacturers`, `categories`, `fitments`, `cross_references` | כולם |
| **שכבה פרטית** | `org_parts` (מחיר, עלות, מלאי, מיקום), `suppliers` | הארגון בלבד |

לקוח חדש מקבל קטלוג מלא ביום הראשון במקום מסך ריק, ובכל זאת המחירים
שלו — המידע המסחרי הרגיש — נשארים שלו. מבקר לא מחובר רואה את זהות
המק"ט בלבד: מספר, שם, יצרן והתאמות. בלי מחיר, בלי מלאי, בלי ספקים.

`Part.for_org(organization_id)` היא נקודת הגישה היחידה לשכבה הפרטית,
וכל מסך, נקודת API וייצוא CSV עוברים דרכה.

| תפקיד | קריאה | עריכת קטלוג | ניהול משתמשים |
|---|---|---|---|
| בעלים (`owner`) | ✅ | ✅ | ✅ |
| מנהל (`manager`) | ✅ | ✅ | ❌ |
| מכונאי (`mechanic`) | ✅ | ❌ | ❌ |

השבתת ארגון מנתקת אוטומטית את כל המשתמשים שלו.

**אבטחה:** סיסמאות ב-scrypt, CSRF על כל הטפסים, קוקיז `HttpOnly`+`SameSite`
ו-`Secure` בפרודקשן, והודעת התחברות זהה לדוא"ל שגוי ולסיסמה שגויה כדי לא
להסגיר אילו כתובות רשומות. `READ_ONLY=1` הוא מתג חירום שחוסם שינוי נתונים
גם למשתמש מורשה.

## התקנה כאפליקציה

האפליקציה היא PWA וניתנת להתקנה למסך הבית — שימושי למכונאי שעובד
מהטלפון ומצלם חלקים.

- **אנדרואיד / Chrome**: כפתור "📲 התקן" בסרגל הניווט, או תפריט הדפדפן ← "התקן אפליקציה"
- **iPhone / Safari**: שיתוף ← "הוסף למסך הבית"

`app/routes/pwa.py` מגיש את המניפסט ואת ה-service worker **מהשורש** ולא
מ-`/static`, כי היקף ה-service worker מוגבל לנתיב שממנו הוגש.

**מה נשמר במטמון:** נכסים סטטיים בלבד. דפים תמיד נמשכים מהרשת, כי הם
מציגים מחירים, מלאי וזיהוי רכב חי — הגשה מהמטמון הייתה מציגה נתונים
ישנים כאילו הם עדכניים. בלי חיבור מוצג מסך ניתוק מפורש.

האייקונים נוצרים ב-`python scripts/make_icons.py`, וגרסת ה-service
worker נגזרת מה-commit כדי שדפדפנים ימשכו נכסים מחדש בכל פריסה.

## הזמנת עובדים

בעלים מזמין עובד מ-`/team`. נוצרת הזמנה עם טוקן אקראי שפג אחרי שבועיים,
והמוזמן בוחר סיסמה ונכנס. אי אפשר להוריד בדרגה או להשבית את הבעלים
האחרון — ארגון לא יכול לנעול את עצמו החוצה.

**דוא"ל:** מוגדר דרך `MAIL_SERVER` ו-`MAIL_SENDER` (ראה `.env.example`).
בלי הגדרה ההזמנה עדיין נוצרת, הקישור מוצג להעתקה ידנית, והמסך אומר
במפורש ששליחת הדוא"ל אינה מוגדרת. כשל SMTP לא מפיל את יצירת ההזמנה.

## מיגרציות

Alembic הוא הבעלים היחיד של הסכימה. `create_all()` כבוי כברירת מחדל —
הוא לא יודע לשנות טבלה קיימת, ושתי מערכות שמנהלות את אותה סכימה סותרות
זו את זו.

```bash
flask db migrate -m "תיאור השינוי"   # אחרי שינוי במודלים
flask db upgrade                      # החלה
```

בפריסה זה רץ אוטומטית ב-`preDeployCommand`.

### מודל הנתונים
`Part` (מק"ט) · `Manufacturer` (יצרן חלפים) · `Category` (קטגוריה היררכית) ·
`CrossReference` (מק"ט מקורי/חלופי) · `Fitment` (התאמה לרכב) ·
`Supplier` + `PartSupplier` (ספקים, מחיר קנייה וזמן אספקה).

### REST API

```
GET    /api/parts?q=&make=&model=&year=&part_type=   חיפוש עם עימוד
GET    /api/parts/<id>                               מק"ט מלא
GET    /api/parts/number/<number>                    לפי מק"ט או מק"ט מקביל
POST   /api/parts                                    יצירה
PUT    /api/parts/<id>                               עדכון
DELETE /api/parts/<id>                               מחיקה
GET    /api/vehicle/<plate>                          רכב לפי מספר רישוי
POST   /api/identify                                 זיהוי חלק + הצלבה מול רכב
GET    /api/stats                                    מספרי מפתח
```

## איתור רכב לפי מספר רישוי

`app/vehicles.py` פונה למאגר כלי הרכב הפתוח של משרד התחבורה
(`data.gov.il`) — חינמי ולא דורש מפתח. אם אין גישה לרשת, המודול נופל
אוטומטית לקובץ `data/vehicles_sample.json` עם עשרה רכבי דמו, כך שהמערכת
תמיד ניתנת להדגמה. מקור הנתונים מוצג במסך (`data.gov.il` מול `offline`).

## קטלוג דגמי הרכב

התאמת מק"ט לרכב היא מה שמפעיל את החיפוש לפי מספר רישוי, ולכן היצרן והדגם
חייבים לבוא מרשימה סגורה: כשהם טקסט חופשי, "טויוטה" ו-"טויוטה יפן" הם שני
ערכים שונים וההצטלבות נכשלת. המקור הוא מאגר "תוצרים ודגמים" הפתוח של משרד
התחבורה — מעל 100 אלף רשומות, שורה לכל שנת ייצור, מכווצות לדגמים עם טווחי שנים.

שתי דרכים לייבא, שתיהן חולקות את `app/vehicle_import.py`:

```bash
python scripts/import_vehicle_models.py            # מהשורה, לפיתוח מקומי
python scripts/import_vehicle_models.py --file x.json   # מקובץ שכבר הורד
```

בפרודקשן דרך היישום: מסך `/admin/vehicle-import`, פתוח למי שכתובתו ב-
`SUPERADMIN_EMAILS`. הייבוא רץ **במנות** — כל בקשה מייבאת כמה עמודים ומקדמת
את נקודת ההמשך, כי משיכה של הכל בבקשה אחת חורגת מה-timeout של gunicorn.
ההתקדמות נשמרת בטבלה `vehicle_import_jobs` ולא בזיכרון, ולכן היא נראית לכל
ה-workers, שורדת נפילה או פריסה מחדש, וניתן להמשיך אותה מהנקודה שנעצרה.

## זיהוי סוג החלק

`app/identify.py` תומך בשתי דרכים, ושתיהן מחזירות מפתח מתוך `app/taxonomy.py`
(42 סוגי חלקים ב-12 קטגוריות):

- **טקסט חופשי בעברית** — התאמת מילים נרדפות. עובד תמיד, בלי רשת ובלי מפתח.
  מזהה גם ניסוחים מדוברים: "דינמו" ← אלטרנטור, "ז'וינט" ← מפרק כדורי.
- **תמונה** — סיווג ויזואלי באמצעות Claude. מופעל אוטומטית כאשר מוגדר
  `ANTHROPIC_API_KEY`, ונופל חזרה לזיהוי מטקסט אם הקריאה נכשלת.

## פריסה ל-Railway

### למה זה לא סתם "לחבר ריפו"

SQLite על הדיסק הרגיל של Railway **נמחק בכל deploy** — כל דיפלוי בונה קונטיינר
חדש עם מערכת קבצים נקייה. לכן פרודקשן דורש Postgres (מומלץ) או ווליום קבוע.

### שלבים

1. **צור פרויקט** ב-Railway וחבר אליו את הריפו הזה.
2. **הוסף שירות Postgres** לאותו פרויקט (`+ New → Database → PostgreSQL`).
   Railway מזריק `DATABASE_URL` אוטומטית, והאפליקציה מתרגמת אותו לבד
   לסכמה ש-SQLAlchemy 2 דורש (`postgresql+psycopg://`).
3. **הגדר `SECRET_KEY`** במשתני הסביבה של השירות:
   ```bash
   python -c "import secrets; print(secrets.token_hex(32))"
   ```
   האפליקציה **מסרבת לעלות** על Railway בלי ערך אמיתי — `SECRET_KEY` חותם את
   קוקי הסשן, וערך ברירת המחדל גלוי לכל מי שרואה את הריפו.
4. **לקטלוג דמו:** הגדר `SEED_DEMO=1`. הזריעה תרוץ רק אם הקטלוג ריק, ולא
   תדרוס נתונים קיימים בדיפלויים הבאים.
5. **Generate Domain** בהגדרות השירות — וזהו.

### מה קורה בכל דיפלוי

```
preDeployCommand:  python scripts/init_db.py     ← יוצר טבלאות חסרות, זורע אם ריק
startCommand:      gunicorn --config gunicorn.conf.py "app:create_app()"
healthcheckPath:   /healthz                      ← בודק גם חיבור לבסיס הנתונים
```

`init_db.py` רץ **פעם אחת** לפני שה-workers עולים, ולכן שני workers לא
מתנגשים ביצירת הטבלאות. הוא בטוח להרצה חוזרת.

> **אל תוסיף שורת `release:` ל-`Procfile`.**
> Nixpacks הופך אותה ל**שלב בנייה** בתוך ה-Dockerfile, ו-Railway לא מזריק את
> משתני השירות לבנייה — כך שכל פקודה שם תרוץ בלי `DATABASE_URL` ובלי
> `SECRET_KEY` ותפיל את הבילד. הכנת בסיס הנתונים שייכת ל-`preDeployCommand`
> ב-`railway.json`, שרץ בזמן פריסה עם כל המשתנים.

### חלופה בלי Postgres

מצרפים Volume, ממפים ל-`/data`, ומגדירים `DATA_DIR=/data`. פשוט יותר,
אבל מוגבל למכונה אחת — בלי scaling אופקי.

### משתני סביבה

| משתנה | חובה | תפקיד |
|---|---|---|
| `SECRET_KEY` | ✅ בפרודקשן | חתימת קוקי הסשן |
| `DATABASE_URL` | מוזרק ע"י Railway | חיבור ל-Postgres |
| `DATA_DIR` | חלופה | נתיב לווליום עבור SQLite |
| `SUPERADMIN_EMAILS` | לגישת ניהול | כתובות בעלות הרשאת-על, מופרדות בפסיק |
| `SEED_DEMO` | לא | `1` = טעינת קטלוג דמו אם ריק |
| `ANTHROPIC_API_KEY` | לא | מפעיל זיהוי חלק מתמונה |
| `WEB_CONCURRENCY` | לא | מספר workers (ברירת מחדל 2) |

הרשימה המלאה ב-`.env.example`.

## בדיקות

```bash
python -m pytest tests/ -q
```

מכסות את זיהוי החלקים, איתור הרכב, הצלבת רכב×סוג-חלק, חיפוש לפי מק"ט מקביל,
מחזור ייבוא/ייצוא CSV וחישובי מע"מ ורווחיות.
